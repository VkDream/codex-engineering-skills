# 用 Codex 做项目：规则与 Skill 分享

这是我在 Windows / Codex Desktop 中使用的一套项目协作规则，整理出来供大家参考。

它给 Codex 约定了几件事：先弄清任务再动手，只改当前需要改的地方，改完做相关检查，最后说清楚“改了什么、测过什么、还有什么没确认”。

小任务可以直接做。需要把开发、审查和验证分开时，再使用下面的六角色流程。

## 里面装的是什么？

主要是给 Codex 阅读的说明文件，加上少量辅助脚本。

| 内容 | 简单理解 | 文件位置 |
|---|---|---|
| 全局规则（AGENTS.md） | 做项目时要遵守的基本约定 | [rules](rules/) |
| 技能（Skill） | 某一类工作的具体做法，如诊断、开发、审查 | [skills](skills/) |
| 知识库模板 | 记录项目位置、当前进度和下一步，供后续任务接着看 | [knowledge-base](knowledge-base/) |
| 可选配置 | 并发数、模型和子智能体的参考设置 | [optional-config](optional-config/) |

这是个人实践分享，不是一键安装的软件，也不是 OpenAI 官方产品。包里没有作者的真实工程、账号配置、聊天记录或知识库历史。

## 这套规则主要管什么？

- **动手前分清范围。** 让它“看看问题”，就先检查；让它“修复”，才在授权范围内修改。
- **改动围绕当前任务。** 不顺手大改架构、升级依赖或动无关文件。
- **做过和没做过分开说。** 没证据就写“不知道 / UNKNOWN”；编译成功不等于界面、设备和生产环境都验证过。
- **交接要说清楚。** 哪个任务负责什么、上一步做到了哪、下一步做什么，都有记录和回传检查，避免漏项或重复做。

这些是对工作方式的要求，不能保证模型永远正确，也不能代替实际验收。

## 六个角色分别做什么？

这里的“角色”指六种职责，不是要求同时运行六个模型。

| 角色 | 负责的事 |
|---|---|
| 00·总监 | 和你确定目标、划清范围，安排任务并跟进结果 |
| 01·诊断 | 查现状、找原因，给出有依据的诊断结果 |
| 02·开发 | 按已确定的任务实现功能，并做相关检查 |
| 03·审查 | 独立检查方案和改动，指出有证据的问题 |
| 04·修复 | 集中修正审查或验证发现的问题，并复查 |
| 05·验证 | 按约定的方式检查实际结果，说明哪些通过、哪些没验证 |

不必把每个小任务都拆成六步。需要这套分工时再明确启用；复制文件本身不会创建六个任务，也不会增加发布、数据库或设备操作权限。

## 第一次怎么用？

先选一个小任务试用，不要直接用整包覆盖已有配置。

1. **把这个仓库下载到本地。** 先看 [全局规则模板](rules/GLOBAL_AGENTS.md)，判断哪些约定适合自己的项目。
2. **让 Codex 检查怎么接入。** 把下面这段话连同下载目录发给它。先得到具体方案，再决定合并哪些文件。
3. **完成必要配置后试一个小任务。** 确认规则和 Skill 确实被读取、检查结果可信，再决定是否启用六角色流程。

可以直接复制这段话，把路径换成自己的：

```text
我下载了一套 Codex 规则分享包，位置是：[填写下载目录]。
请先只读检查它与我现有规则是否冲突，并确认本机的规则和 Skill 加载位置。
告诉我哪些文件可以用、哪些路径需要替换，以及建议的最小接入方案。
这一步不要覆盖现有配置、执行安装脚本或创建六个角色任务，等我确认方案后再修改。
```

下面是实际配置时需要看的细节。第一次了解这个仓库，可以先跳过。

<details>
<summary>配置细节：替换路径、放置文件</summary>

这些文件是模板，里面的占位符需要手动替换，不会由 Codex、PowerShell 或 Node 自动展开。

| 占位符 | 要替换的值 |
|---|---|
| `{KB_ROOT}` | 知识库根目录，例如 `C:\ExampleKB` |
| `{SKILLS_ROOT}` | 七个 Skill 文件夹安装后的共同父目录 |
| `{SKILLS_ROOT_URI}` | 同一目录的绝对 file URL，例如 `file:///C:/ExampleSkills`；空格等字符需正确编码 |
| `{GLOBAL_AGENTS}` | 实际生效的全局 `AGENTS.md` 文件的绝对路径 |

先替换 `{SKILLS_ROOT_URI}`，再替换其余占位符，并检查引用是否指向实际文件。只在本包副本中替换，不要对整台电脑批量替换。

- 将 `knowledge-base` 的内容放在选定的知识库根目录；其中的“示例项目”是未启用模板，需要按实际项目填写。
- `rules/GLOBAL_AGENTS.md` 供阅读、比较和合并，不会仅凭这个文件名自动生效。已有 `AGENTS.md` 时先备份、比较再合并。
- 按 [OpenAI Skill 文档](https://developers.openai.com/codex/skills)，本地 Skill 可放在项目或用户目录下的 `.agents/skills`。复制 `skills` 里面的七个文件夹（六个角色 + 一个路由），保留各自的 `SKILL.md`、`references`、`scripts` 和 `agents` 结构。不要多套一层目录或重复安装同名副本；自定义环境以实际加载位置为准。

模板默认禁止未经明确授权的 Git 调用，包括只读命令。使用前请了解这条规则，并按自己的授权政策决定是否保留或调整。

</details>

<details>
<summary>运行条件：哪些能力需要另外准备？</summary>

普通任务可只使用所需规则。若要自动在六个角色之间分派任务，当前 Codex 客户端还必须提供创建任务、读取任务和发送消息的工具。缺少这些工具时，只能参考流程，不能声称自动派发已完成。

本包不提供 MCP 服务、浏览器工具、第三方插件或模型订阅。规则中提到的工具，需要在使用者环境中实际可用。

当前接力的回传辅助脚本要求主任务记录（`MASTER_RUN`）使用 Windows 绝对路径；macOS / Linux 的完整接力尚未适配验证。Node.js 用于回传辅助模块；Python 和 `headroom-ai` 仅用于可选的 Headroom 评估，阅读和使用普通规则不要求安装它们。

规则还约束后台进程的启动和清理：只管理当前任务能确认归属的进程，不按进程名批量结束其他任务。

</details>

<details>
<summary>可选配置：模型、并发和 DSH</summary>

`optional-config` 是参考设置，不要整份替换现有 `config.toml`。合并前先备份，并确认本机版本支持相关字段及子智能体配置的加载方式。

模型表表达的是作者的选择，不代表你的账号拥有相同模型、Fast 服务层或并发能力。并发 8 是上限，不要求每次开满；客户端若有更低限制，以实际限制为准。

配置变动按客户端要求重启生效；仅阅读本包无需中断正在运行的任务。DSH 的模型由使用者自行选择，本包不修改 DSH，也不把 Codex 模型配置移植到 DSH。

</details>
