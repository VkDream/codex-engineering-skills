# Codex 项目工作流：个性化、知识库与六角色 Skill

这是我在 Windows / Codex Desktop 中做项目时使用的一套工作方法，包含个性化指令、知识库模板和六角色 Skill。

我用它约定 Codex 的工作方式：先弄清任务再动手，只改当前需要改的内容，改完做相关检查，最后说清楚“改了什么、测过什么、还有什么没确认”。

小任务可以直接做。需要把开发、审查和验证分开时，再使用下面的六角色流程。

第一次使用，请从 [从零开始搭建工作流](从零开始.md) 看起；只想了解我的个性化设置，可以直接看 [个性化设置说明](个性化设置.md)。

> 本页原文为简体中文。如果页面上的句子不通顺或代码与文字顺序错乱，请先关闭网页翻译，查看原文。

## 这套工作流包含什么？

主要是给 Codex 阅读的说明文件，加上少量辅助脚本。

| 内容 | 简单理解 | 文件位置 |
|---|---|---|
| 个性化指令 / 全局规则 | 约定 Codex 怎么做事、什么时候能修改、怎样报告结果 | [rules/GLOBAL_AGENTS.md](rules/GLOBAL_AGENTS.md) |
| 技能（Skill） | 某一类工作的具体做法，如诊断、开发、审查 | [skills](skills/) |
| 知识库模板 | 保存项目位置、当前进度和下一步，换任务后也有记录可查 | [knowledge-base](knowledge-base/) |
| 可选配置 | 并发数、模型和子智能体的参考设置 | [optional-config](optional-config/) |

这份分享包包含说明文件和辅助脚本，需要按自己的环境配置。它由我个人整理，与 OpenAI 官方产品无关；包里没有我的真实工程、账号凭据、聊天记录或私人知识库内容。

## 这套规则主要管什么？

- **动手前分清范围。** 让它“看看问题”，就先检查；让它“修复”，才在授权范围内修改。
- **改动围绕当前任务。** 不顺手大改架构、升级依赖或动无关文件。
- **做过和没做过分开说。** 没证据就写“不知道 / UNKNOWN”；编译成功不等于界面、设备和生产环境都验证过。
- **交接要说清楚。** 记录谁负责什么、已经做了什么、下一步要做什么，并核对交回的结果，避免漏项或重复工作。

这些是对工作方式的要求，不能保证模型永远正确，也不能代替实际验收。

## 六个角色分别做什么？

这六个角色按职责分工，使用时不需要让六个模型同时运行。

| 角色 | 负责的事 |
|---|---|
| 00·总监 | 和你确定目标、划清范围，安排任务并跟进结果 |
| 01·诊断 | 查现状、找原因，给出有依据的诊断结果 |
| 02·开发 | 按已确定的任务实现功能，并做相关检查 |
| 03·审查 | 独立检查方案和改动，指出有证据的问题 |
| 04·修复 | 集中修正审查或验证发现的问题，并复查 |
| 05·验证 | 按约定检查实际结果，分别说明通过、未通过和未验证的部分 |

小任务不必走完六个角色。需要分工时，再明确要求 Codex 启用这套流程。复制文件不会自动创建角色任务；发布、数据库写入和设备操作仍需另行授权。

## 第一次怎么用？

先按 [搭建指南](从零开始.md) 准备个性化设置、知识库和 Skill，再选一个小任务试用。已有配置请先备份、比较，再决定合并哪些内容。

1. **把这个仓库下载到本地。** 先看 [全局规则模板](rules/GLOBAL_AGENTS.md)，判断哪些约定适合自己的项目。
2. **让 Codex 检查如何配置。** 把下面这段话连同下载目录发给它，让它先给出方案，再由你确认要改哪些文件。
3. **配置好后，先试一个小任务。** 检查 Codex 是否读取了规则和 Skill、是否如实报告了检查结果，再决定是否启用六角色流程。

可以直接复制这段话，把路径换成自己的：

```text
我下载了一套 Codex 规则分享包，位置是：[填写下载目录]。
请先阅读 README、从零开始.md 和个性化设置.md，再只读检查这套规则与我现有配置是否冲突。
确认本机的全局指令和 Skill 存放位置，以及我是否已经有知识库。
告诉我需要配置哪些文件、替换哪些路径；如果需要新建知识库，请先提出方案。
这一步不要覆盖现有配置、执行安装脚本或创建六个角色任务，等我确认方案后再修改。
```

以下内容供配置时查阅；第一次了解这套工作流，可以先跳过。

<details>
<summary>配置细节：替换路径、放置文件</summary>

模板里的 `{KB_ROOT}` 等标记代表你自己的路径，使用前必须明确替换。它们不是环境变量，程序不会自动把这些标记转换成真实路径。

| 占位符 | 要替换的值 |
|---|---|
| `{KB_ROOT}` | 知识库根目录，例如 `C:\ExampleKB` |
| `{SKILLS_ROOT}` | 存放这七个 Skill 文件夹的目录 |
| `{SKILLS_ROOT_URI}` | 同一目录的绝对 file URL，例如 `file:///C:/ExampleSkills`；空格等字符需正确编码 |
| `{GLOBAL_AGENTS}` | 实际生效的全局 `AGENTS.md` 文件的绝对路径 |

先替换 `{SKILLS_ROOT_URI}`，再替换其余占位符，并检查引用是否指向实际文件。只在本包副本中替换，不要对整台电脑批量替换。

- 将 `knowledge-base` 的内容放在选定的知识库根目录；其中的“示例项目”是未启用模板，需要按实际项目填写。
- `rules/GLOBAL_AGENTS.md` 是我的个性化指令分享版，需要按 [个性化设置说明](个性化设置.md) 合并到实际生效的全局指令中。仅把文件放在本仓库里，不会让这些规则自动生效。已有 `AGENTS.md` 时，请先备份、比较，再合并。
- 按 [OpenAI Skill 文档](https://developers.openai.com/codex/skills)，Skill 可以放在项目或用户目录下的 `.agents/skills`。请完整复制 `skills` 下的七个文件夹：六个角色 Skill 和一个路由 Skill。保留各文件夹内已有的 `SKILL.md`、`references`、`scripts` 和 `agents`；不要额外套一层目录，也不要重复安装同名 Skill。自定义环境以实际加载位置为准。

模板要求先获得明确授权，才能执行 Git 命令，连只读命令也包括在内。使用前请了解这条约定，并根据自己的项目要求决定是否保留或调整。

</details>

<details>
<summary>运行条件：还需要准备哪些工具？</summary>

普通任务可以只用需要的规则。若要让六个角色自动交接，当前 Codex 客户端必须提供创建任务、读取任务和发送消息的工具。缺少这些工具时，可以参考分工方式，但不能把手动操作说成已经实现自动交接。

本包不提供 MCP 服务、浏览器工具、第三方插件或模型订阅。规则中提到的工具，需要在使用者环境中实际可用。

自动交接使用的结果回传脚本需要 Node.js，并要求主任务记录文件（`MASTER_RUN`）使用 Windows 绝对路径。macOS / Linux 上的完整交接流程尚未适配验证。

Python 和 `headroom-ai` 只用于可选的 Headroom 评估；阅读和使用普通规则不需要安装它们。

规则还约束后台进程的启动和清理：只管理当前任务能确认归属的进程，不按进程名批量结束其他任务。

</details>

<details>
<summary>可选配置：模型、并发和 DSH</summary>

`optional-config` 提供个性化风格、模型和并发的配置示例。请先确认本机版本支持这些设置，再按需合并；不要用示例文件覆盖整个 `config.toml`。

模型表表达的是作者的选择，不代表你的账号拥有相同模型、Fast 服务层或并发能力。并发 8 是上限，不要求每次开满；客户端若有更低限制，以实际限制为准。

配置变动按客户端要求重启生效；仅阅读本包无需中断正在运行的任务。DSH 的模型由使用者自行选择，本包不修改 DSH，也不把 Codex 模型配置移植到 DSH。

</details>
